# 微分动力：矿车

本版适配 Minecraft 1.21.1 的普通、熔炉、箱子、漏斗和 TNT 矿车，以及 Create 矿车装配体。沿用轨道连接、弯道、坡道、载客、容器、燃料、探测和激活规则。列车不使用本模型。

## 底车标定

底车等效惯量统一取 **0.01 su/RPM³**，与普通动力机器本体一致。原版空车只能确定驱动与惯量、阻力与惯量的比值，不能唯一确定绝对质量；采用这个值便于与现有结构惯量共用同一标定。

参考运动坐标沿用活塞：每圈对应 `1200/512 = 2.34375` 格，原生运动向量一格/tick 对应 512 RPM。惯量、力矩、功率与能量继续使用轴系单位，不另设公斤或牛顿。

| 未装配行为 | 保留的原版标定 |
| --- | --- |
| 普通车惰行 | 每 tick 水平速度乘 0.96 |
| 载客车惰行 | 每 tick 乘 0.997；原生载客位移倍率仍保留 |
| 箱子、漏斗车 | 保留容器满度决定的原生浮点阻力系数 |
| 动力铁轨 | 移动车每 tick 增速 0.06；靠实心方块起步的原生增速为 0.02 |
| 未通电动力铁轨 | 每 tick 速度乘 0.5，低速停止门槛为 0.03 |
| 熔炉驱动 | 保留原生的 `v_next = 0.8v + 推进方向`，随后施加底车阻力；无推进时另乘 0.98 |
| 燃料 | 保留燃烧时长、玩家添煤和 Create 从车载库存自动补燃料 |
| 水中 | 保留原生水中减速及熔炉推进倍率 |

原版存储的运动向量可高于轨道实际位移上限，两者分别保留。因此本版的等效动能是该原生运动坐标的储能标定，不将其直接称为现实世界的平动动能。轨道几何和原生速度上限仍可能耗散这份储能。

## 装配质量与阻力

装配体使用[活塞已有的质量规则](CONTRAPTIONS.md#质量与惯量)：每个非空气方块的结构质量系数为 0.0006，输入端惯量为 `M×[1200/(512×2π)]²`。一个方块增加约 0.0000834861 su/RPM³；底车相当于约 120 个结构方块的平动惯量。

结构质量包含稳定子结构，每个实体只计一次；两辆矿车支撑同一个装配体时各承担一半。结构方块材质和库存物品种类不改变质量。底车固定设备及普通乘客仍通过原生行为标定，不在本版另加逐物品、逐实体质量。

静止结构接入时，车速按旧/新惯量比降低；移除结构时底车保留当前速度，结构带走其份额。读取已保存的惯量摘要不会重复支付组装损失，子结构尚未加载时保留完整摘要。

底车阻力对应固定阻尼能力。装配后按总惯量重新积分，并叠加结构外露面的平方空气阻力；结构朝向影响迎风投影。Create 装配体不计作普通坐席乘客，不触发原版的载客减阻与位移倍率。

## 有限驱动与联结

动力铁轨、控制铁轨和装配站的驱动按底车标定提供有限力矩；载荷增加会降低加速度。控制铁轨的 0–15 信号仍给出方向和速度目标，每 tick 的调速能力最多相当于底车增速 0.4。刹车也受惯量影响，不直接把重车赋值到目标速度。

通电铁轨仍是 Minecraft 提供的外部能源，不要求连接动力轴。动力铁轨参考力矩为 368.64 su/RPM，调速轨为 2457.6 su/RPM；正做功分别受 383149.6704 su 和 2768240.64 su 的功率上限约束。上限按两格/tick 加上本 tick 的增速计算完整动能增量，保留载客动力车在原生存储速度上限处的行为。

熔炉沿用原生驱动曲线，附加有限力矩和正做功上限：每 tick 的最大参考速度改变量为 2，最大正功率为 4341104.64 su，覆盖原生驱动将存储速度从 2 提到 2.6 的过程。负载增加改变曲线的惯性响应；燃料停供后撤去推进，保留惰行。Create 补燃料回调只维护推进方向和燃料，不再同时把运动向量归一化为一格/tick。

联结速度反作用使用两车实际惯量和被动弹簧/阻尼，重车不会获得与轻车相同的速度修正。暂停或冻结端不接收运动，也不会以其暂存速度驱动邻车。原生联结硬位置校正仍用于处理轨道几何约束；本版没有加入联结断裂或跨整个车队的统一约束求解。

## 连续工具作业

钻头、锯、收割机、犁和滚轮通过 [ActorDrive](../src/main/java/com/diliupengyun/differential_create/kinetics/ActorDrive.java) 与活塞、动力轴承共用 [ContraptionActorWork](../src/main/java/com/diliupengyun/differential_create/kinetics/ContraptionActorWork.java) 的目标、进度、完成和掉落规则。矿车没有动力轴，其作业预算由底车运动提供，不伪造动力轴控制器。

工具进给按轨道上的实际位移计量，沿途在体素边界和作业完成点分段，防止越过尚未切完的目标。切削冲程沿用最多四分之一格的标定，目标硬度决定总工作量；耗功从矿车存储运动坐标的动能中扣除。轨道位移上限与存储速度不一致时，按两者的速度比折算惯量，使进度仍跟随实际进给，而不是存储向量的长度。

转向也提供工具进给。按原生 tick 的顺序，在平移后分别积分偏航和俯仰的圆弧，并检查圆弧穿过的中间体素，而非仅检查两端或端点间的直线。稳定子结构沿安装点的轨迹移动，并保留原生的朝向稳定方式。改变速度、转向比例或姿态阶段时，部分任务按实际位移折算剩余冲程；负载力矩和已付进度使用同一事件的比例。

单车的正常转向模式允许作业，锁定朝向模式不产生转向进给，转向时暂停模式在尚未对齐时禁止作业，最后对齐的一步恢复付费作业。双车支撑沿用原版的独立姿态分支，该分支不受这三种单车旋转模式限制。转向耗功由可移动的支撑车按各自可用动能分摊，静止或被暂停的支撑不提供切削能量；工具只完成和掉落一次。

服务端接受的付费姿态通过原生实体数据同步到客户端，避免客户端继续按未受负载限制的角度转向。专项测试检查真实数据包编码、解码及迟加入时的姿态初值；多人延迟、插值观感和动画仍需实机验收。

钻头切削不会设置原生的全车暂停标记，也不按原生 `TicksUntilNextProgress` 或落沙后的 `WaitingTicks` 推进。动能不足可以真正减速至零，尚未完成的切削进度保存在工具 NBT 中；零速度和真实碰撞不能继续提供进给，恢复动力后继续已付费的部分。反向退刀、关闭工具、目标替换与拆解会取消失效作业。

工具只观察正在作业的世界目标；玩家在两个物理 tick 之间拆掉并放回同种方块，也会使旧进度失效。失效标记随工具 NBT 保存。收割机、犁和滚轮会重新检查同格目标、地面和材料可用性，关闭后再开启或补货可以重新取得作业。滚轮零速度保留进度与材料预留，取消或拆解时退款一次。

动力铁轨在本 tick 的切削使车速落入原生低速起步区时，沿已知进给方向继续提供有上限的推进冲量。未装配车仍保留原生靠实心方块起步的行为。熔炉燃料和控制铁轨也可以补充后续切削的运动预算。双车承载结构只由实际乘载该结构的底车调度工具一次；平移反作用通过联结传递，转向耗功直接分摊到可移动的两辆支撑车。

离轨时同样对实际三维位移分段扣除工具工作；底车的原生地面、空中运动和碰撞规则保留。进给方向随矿车 NBT 保存，熔炉从库存补煤后能重新启动停转作业。熔炉装配/拆解的原生实体读回不会使 Create 控制器丢失矿车引用。

机械手和便携存储接口等驻留动作仍保留原生等待流程，尚未接入独立的作业动力模型。

## 验证与边界

数值入口为 [MinecartRegression](../src/physicsTest/java/com/diliupengyun/differential_create/MinecartRegression.java)，真实游戏入口为 [MinecartIntegrationTests](../src/main/java/com/diliupengyun/differential_create/tests/MinecartIntegrationTests.java)。原生实体逐 tick 对照 Minecraft 的独立速度递推和实际位移，另外检查燃料、组装动量、重复刷新、重载、拆解、有限驱动及双车支撑。

验证：构建及全套数值回归通过，其中矿车数值检查 5668 项；完整运动 GameTest 1298 项通过，包含 715 个矿车场景，其中转向专项为 280 个；常规机械与流体 GameTest 247 项通过，包含活塞和轴承。详细入口、玩家操作、判据和未覆盖范围见[测试覆盖表](MINECART_TEST_MATRIX.md)。未装配直轨对照覆盖两个轴、正反方向及连续 64 tick；另外检查全部十种轨道形态的原版轨迹和速度修正。

```powershell
.\gradlew.bat build
.\gradlew.bat runMotionCoverageServer '-PmotionSelect=minecart_.+'
```

实体碰撞、原生坡道修正和联结硬位置校正保留原有处理，目前不能宣称完整车辆机械能守恒。短工具的坡道接触、弯道进给、长臂转向圆弧、双车俯仰与复合姿态、稳定子结构以及三种旋转模式已有自动测试。姿态按原生离散 tick 顺序分段，不是同时平移与旋转的六自由度车体求解器。复杂车队、自然区块卸载重载、跨维度和多人客户端体验仍需专项验收。

维护入口为 [MinecartMotion](../src/main/java/com/diliupengyun/differential_create/kinetics/MinecartMotion.java)、[MinecartPhysics](../src/main/java/com/diliupengyun/differential_create/kinetics/MinecartPhysics.java) 和 [MinecartActorMotion](../src/main/java/com/diliupengyun/differential_create/kinetics/MinecartActorMotion.java)。
