# 微分动力：思索与物品提示

微分动力（Differential Create）的思索优先沿用 Create 原版教程。尽可能保留场景摆放、底板、镜头、缩放、字幕位置、指示效果和播放节奏；只有与当前模组规则或真实求解结果矛盾的部分才做最小修改，中英文同步维护。初始库存、动力输入、投料和玩家操作可以由脚本安排，转速、液位、加工进度、产物、制动和位移不能按时间写死。真实加工需要更长时间时，等待机器完成，不提前替换成品。新增机制使用独立补充教程，不整段替换原版故事板。

尚未接入动力的模板组件，其转速设置属于初始条件，不能在后来接入时回放为上游动力源的变速或停机指令。组件接入动力后的正式操作仍会传递到动力源。原版管道与速比控制器的预设倍率在输入元件入场前完成，避免先按模板转速启动再突然降速；容器管道的入口先保持停止，再按原操作启动。离合器补充教程保持输入端运转，只通过离合器断开传动，单独展示输出端依靠惯性续转。

新增教程按讲解对象选择配角，不固定采用“创造马达＋飞轮”。普通机器沿用原版离合器、仪表教程的外部动力接法：底板侧缘的大齿轮中心位于底板层（y=0），斜上方的小齿轮与它啮合，再用传动轴接入舞台；较高的轴系通过小齿轮逐级抬升，不把孤立的大齿轮悬在高处的长轴末端。边缘大齿轮从下方随舞台显露，小齿轮和台内元件从上方接入。驱动指令按实际啮合速比换算，保留台内轴的目标转速和方向。只有明确登记的边缘大齿轮可以提供有限扭矩，断开的从动件不会自行获得新动力。粉碎轮的两路输入各自向外错开放置底部大齿轮，避免一个大齿轮同时啮合两列小齿轮。创造马达本身的原版教程仍保留。

飞轮仅保留在“扭矩、惯量与储能”和“连续加工”的储能演示中。离合器用钻头展示输出端惰行；速比控制器使用普通齿轮，负载表以鼓风机的真实风阻展示带载平衡和断供惰行，转速表的边缘齿轮通过传动轴接表；可编程齿轮箱驱动轴承和带白色端部的木臂，以显示转角、反向和到位保持，木臂惯量及空气阻力按实际方块几何计算；蒸汽引擎接普通大齿轮，断汽后依靠动力轴自身的真实惯量惰行。不能为了保留慢转效果，给无惯量齿轮虚构惯量或隐藏飞轮。

流体储罐沿用原版的储存流体、储罐尺寸两篇教程；锅炉与蒸汽动力内容归蒸汽引擎，不在储罐入口重复添加。

共 19 个独立物理教程主题。部分主题由多个部件共享；物品与流体接口、两种离合器使用对应模型。原版离合器、速比控制器、仪表、泵、轴承、移动接口、可编程齿轮箱和列车控制教程仍使用原来的 NBT 模板、故事板、标签和排序约束。原版文字只修正与模组规则冲突的句子，不为缩短文案而改写正确内容。

流体阀门的开关、智能流体管道的过滤沿用各自已有的原版教程。智能管道末段先保留源头已耗尽巧克力的过滤器，避免泵断开输入后靠惯性提前抽走牛奶；完成两条分支的过滤设置后，再移除源头过滤器、补充巧克力并启动输入。牛奶过滤器移到岔口紧邻的一格，其后管道沿新增的一排底板绕回原储罐；否则巧克力会先灌满过滤器前的弯管，阻挡后续牛奶。两罐、泵和动力入口的位置不变。牛奶罐预置少量匹配液体，巧克力罐保留前段实际收到的库存。两罐的液位只作可视库存对照，不再产生接口压头或决定取液资格。末段字幕内必须各有至少 500 mB 的新增匹配液体，并检查渲染液面实际上升；字幕放在画面上方，避免挡住储罐和过滤器，不能只凭罐中已有对应液体通过检查。空气仍可通过过滤管，规则详见流体机制文档；分类演示的字幕直接说明过滤操作和两种液体的实际去向。普通管道的新增教程只演示空管进液和排气，不再混入阀门、过滤部件，也不挂到泵、阀门、智能管道、储罐和软管滑轮。两个罐、泵、传动和底板保持原有位置；脚本只给起初为空的供水罐装水并启动动力，管内水气前沿、排气量和接收液位均由真实求解产生。

阀门原版场景在固定操作后等待实际开闭完成，不按 22 tick 强制写开关结果；开关操作的原文字幕延长至覆盖实际行程。手轮绕自身竖轴旋转时，以方块中心核对连接，不能用旋转后的角点把它误判为脱离阀门。智能管道原版场景按当前流体 ID 准备巧克力和牛奶，在源端过滤设置完成、泵启动时才供料，避免旧模板液体缺失和重力提前送料。两段原版场景均检查实际接收结果，分别验证开阀通液、关阀，以及两路过滤后的巧克力和牛奶。

注液器的注液粒子和完成喷溅随所属显示区域同步平移、旋转，复用机器粒子的坐标转换；原版储罐教程末段的注液器平移后，粒子不能留在模板坐标。储罐和注液器教程取消定时脚本喷溅，改由真实填充过程触发。注液器模板的旧格式蜂蜜库存使用当前格式恢复为原有的储罐 10000 mB、注液器 1000 mB，后续输送和消耗仍走实际处理。[PonderSpoutAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderSpoutAudit.java) 在两段原版故事板中拦截实际粒子发射，核对喷嘴、接收物品的位置、液体种类、加工阶段和每件成品的一次完成喷溅，并比较正常播放与跳转重播。

## 文案与阅读时长

正文每屏只讲当前演示的操作或机制。详细数值、拆装操作和边界条件仍可在物品提示及机制文档中查询，不把完整说明书塞进一个短字幕。标题始终显示，不按短字幕计时。

新增教程优先说明玩家能做什么、会看到什么。例如将“轴行程”解释为轴实际转过的圈数，将“惰行”写成断电后靠惯性继续转动，将接口计时和占用设置说明为延后断开及对接信号。读表公式、调节范围、快捷键和影响操作的数值保留，不把简化文案写成与物理机制矛盾的绝对说法。

描述比较结果时，画面须有实际对照。鼓风机分别在两种转速下重新投入同一种矿石，完整等待原版加工计时和真实产物，不能只加快叶片后宣称加工时间相同。列车 N 档演示实际给油门，让引擎转动而车轮停止；字幕只指向这一可见差别。可编程齿轮箱使用较慢输入展示转角、反向和定位，结束后等待输出实际停稳，再发下一次红石脉冲。

共用动力学教程的冲压只由原生置物台配方回调处理，不再叠加另一套加工指令。启动和惯性演示使用同一批铜锭，中途实际拆开输入轴，保留可见断口；飞轮靠储存的能量继续加工，不能只把隐藏动力指令改成零。每批完成并回程后才收走成品、开始下一批，并显示收取操作。末段先从侧面展示空载齿轮速比，再转向置物台，在对照字幕出现时同时给两台放入各两个铜锭；逐件接触、剩余铜锭、成品数量和两台完整回程都必须核对。两只置物台都要看清，增速侧用绿框、普通侧用白框。共用教程录制可指定 `-PponderVideoComponent=create:copper_valve_handle`，核对指定入口自身的图标和故事板。

思索中的冲压遵循原生置物台的成品落位：之前压出的铜板由 [PonderDepotOutput](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderDepotOutput.java) 合并到同一个边缘槽，最后一个铜锭压成的铜板留在中央。只整理真实配方已经生成的边缘输出，保留全部数量和物品数据，中央原料仍按真实接触逐个消耗。堆叠外观直接使用 Create 原生置物台渲染：1～3 个物品显示 1 层，4～15 个显示 2 层，16～63 个显示 3 层，64 个显示 4 层。层数不等于实际数量，不为思索额外改成每片一层。播放检查核对固定落位、接触时机和数量守恒，倒带比较各槽库存；独立夹具覆盖无动力、1 件、4 件及 64 件原料、部分及全部加工后的保存读取和成品收取。

[PonderTextAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderTextAudit.java) 随思索客户端测试运行，从真实编排中读取每条字幕的显示时长，并检查中英文。阅读预算只约束全部自定义主题；本模组改写的原生场景仍逐条记录读数，但原生教程保留 Create 自己的节奏，不因超预算判定失败。

- 以每秒 **5 个汉字、3 个单词**作为通过标准，同时记录每秒 8 字、5 词的快速阅读用时。
- 混排文字的时间相加：`汉字数 / 5 + 英文、按键及数值词数 / 3`。标点和格式符不计；连字符、斜杠分隔的词分别计数。
- 按正常播放的每秒 20 tick 计算，扣除淡入淡出；不依赖暂停、慢速阅读或额外拖长停留时间。
- 自定义正文保留原来的 90 tick 阅读时间和 100 tick 编排间隔。原生场景保留各自时长与原文，不按阅读预算精简。
- `markAsFinished()` 只开放下一场景，现有字幕仍继续计时；检查不会误把时间轴结束标记当成字幕消失。

统计明细输出至 `build/ponder/previews/text-readability.json`；自定义主题超出慢速阅读预算会使客户端检查失败，原生场景的读数仅作参考。

原版离合器既不消耗应力，也不提供应力容量，没有对应的常驻统计条。微分动力新增的离合器限扭放入 Shift 的“机械属性”，直接显示普通／黄铜离合器完全接合时的额定上限；不套用动力源容量的“小／中／大”分级。

软管滑轮的显示位移由实际游戏和思索共用的 [HosePulleyAnimation](../src/main/java/com/diliupengyun/differential_create/client/HosePulleyAnimation.java) 处理。完全收起时保留原模型所需的 3/16 格间距，在最初一格行程内平滑消除这项外观补偿，起步和收回均连续可见；一格及以上与原显示位置完全一致。普通渲染与 Flywheel 读取同一结果，不更改真实放管量、抽水位置、碰撞或存档，不在思索中添加定时下降动画。

软管滑轮的抽放水、液位教程沿用原版可见布局和底端直管，不额外显示供液储罐。原模板在直管下方隐藏的创造流体储罐，改由 [PonderFluidBoundary](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderFluidBoundary.java) 提供有限的场外库存；脚本只初始化库存，实际取液、输送、回收和水方块增减仍由生产流体机制完成。场外接口随管口的场景位移计算高度，重播时清空并重新初始化；库存计入逐 tick 水量守恒检查。

长动作的实际耗时由原版 `idle()` 排入教程总时间，进度条随模拟持续推进，不单独冻结或倒退。软管的抽放水和液位教程保留 256 RPM 的舞台外泵驱动；抽放水教程先完成注水和软管下放、停稳，再反转泵抽水，水方块仍由实际输送产生和抽走。`PonderAwait` 只在预留时间之后检查结果，不按时写入结果。调整动力输入、操作时刻或配方后，需要重测耗时；下放期间额外多摇几 tick 会改变进水口深度，不能随意用更长的操作代替停车等待。[PonderTimingAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderTimingAudit.java) 检查连续推进、预留时间是否覆盖实际动作、关键帧跳转和重播，并用故意漏算时间的场景验证检测有效。

无限水源教程在接触水面前松开曲柄，惯性下放并停稳后才开始抽水；末端保持在原版可见水层内。检查覆盖整个下放过程的最大伸长量、最终三格深度、真实入罐水量和跳转重播，避免只验证能抽到水而漏掉末端伸出舞台的问题。

## 维护与验证

移动式流体接口沿用原版模板、镜头和八段字幕，由 [PonderFluidInterfaceScene](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderFluidInterfaceScene.java) 调整操作与等待时间。开场的舞台外输入按实际角度减速并制动，转一圈停稳后解除挂载，再展示粘合与接口间距；讲解结束后重新组装转动。对接、停稳、库存开放、超时收回均采用实际接口状态，不能写入 `Timer` 来伪造连接。原有边缘齿轮驱动泵，调整其输入目标和初始供液量，让两个移动罐都能实际装入巧克力并抽回。正文时间线包含实际装卸和收回所需时长。

对应字幕检查要求安装期间结构静止、连接讲解期间接口可用、两个移动罐在装卸字幕期间都有明显库存变化，且三罐与管网总量始终守恒。正常播放、跳转播放和再次重播对比运动与对接状态；连续录像另核对粒子、指示位置及液面。共享接触判定仅在两端朝向误差不超过 2° 时进入制动，保留原有平移搭接范围，避免明显偏斜时锁死并开放库存。

移动式接口的两个预览模型共用实际对接状态作为伸缩和连接指示的来源，移动端不能再由原版空连接计时器每 tick 把动画清零。该绑定只影响显示，不给移动端模板开放库存权限；移除绑定时恢复各自状态。单个 tick 内发生多次状态更新时保留前一 tick 的插值起点，伸缩只由当前接受的最终状态决定。动画检查同时核对跨 tick 连续性和 tick 内的中间帧，连接期间两端都必须保持伸出。

移动式物品、流体接口共用的“红石控制”教程保留原版模板、镜头、原文和 80 tick 的完成标记。开场在静止结构上完成真实对接，操作原版拉杆后关闭库存、收回接头，再由实际输入驱动转动；固定端读取真实相邻红石信号，通电期间不尝试捕获。与原版的非阻塞转动指令一样，完成标记之后动画可以继续，不将剩余旋转时长追加到进度条。检查分别覆盖两种接口的开场连接、先收回再移动、通电经过不停靠，以及正常／跳转／再次播放，不能按共用的场景 ID 把流体版本去重掉。

接口补充教程专门讲扳手选项，省去重复的安装、停靠介绍。初始在可对接位置组装，选择“等待红石”，在无货物条件下保持超过默认超时，再操作拉杆放行；随后分别演示“占用期间”和“对接阶段”输出。朝向玩家的比较器和红石线读取真实接口状态，不能预设 0、8、15 的演示结果。配置界面使用原生图标选项板；默认自动放行与连接信号、旧设置存档的兼容性由客户端检查覆盖。

蒸汽引擎的喷汽位置与喷射方向使用引擎所在展示区块的变换，与烈焰人燃烧室和注液器共用粒子坐标换算。模板中尚未展示的引擎可以参与锅炉与传动计算，但不发射粒子，避免在原始模板坐标留下悬空蒸汽。

蒸汽动力补充教程通过明显移走热源演示断汽，不能将燃料耗尽等同于空燃烧室：有烈焰人的燃烧室会留下余烬，仍可能提供被动热量。断汽字幕出现时，热源必须已移走、供汽扭矩为零，动力轴仍依靠自身惯量转动。风车原版教程的右击拆解按实际结构归位到方块网格，不叠加只适用于原版固定动画的角度修正。

起重机的小齿轮使用独立的角度入口，普通渲染和 Flywheel 共用连续积分角，不能再用当前转速乘全局时间。渲染回归覆盖 12 种朝向、变速、反转、惰行和三个插值时刻，另改变全局时钟确认相位不随之跳变。

思索是实时绘制的教学场景：NBT 模板提供方块和初始状态，Java 故事板按 tick 安排显露、移动、提示与操作；`PonderLevel` 是独立的客户端预览世界。微分动力把轴系运动接入共享扭转求解器，但这不等于整个预览都运行完整服务端物理。判断一致性必须同时检查场景脚本、实际机器状态和最终渲染，不能只看求解器的角度连续。

负载表从刚完成积分的实际动力曲线、工作阻力、局部转速、离合器损耗和装配体负载计算读数，惯性及弹性储能不计作持续需求。转速表读取本地实际轴速；所有仪表、比较器及其输出红石线在故事板指令执行后统一刷新，旧 NBT、手写指针和开关红石不能覆盖测量结果。原版显示链接的“1024 su”示例改为读取正在展示的负载表；该表没有动力时显示“无动力”。这些修改只涉及预览，不修改游戏世界的采样时机。

原版负载表教程在原有两个位置用机械锯替代同轴空转粉碎轮，分别放入一根原木，按真实配方和轴行程切割；作业结束后释放负载。比较器讲解时再投放原木，观察真实信号变化。其余舞台、镜头、字幕顺序和时间安排保留。新增负载表教程删除预设的 35%、100% 和无穷大读数，以鼓风机持续风阻得到实际平衡读数，再切断动力显示无读数惰行。

方向粒子读取发出时的真实转向，不提前采用尚未达到的目标方向。粉碎轮预览使用生产求解器的双轮作业接触，两轮受到大小相等、方向相反的反作用，作业耗功按相对运动计算；同向差速时慢轮能收到回传功率，不能把两轮都当作独立阻力负载。

[PonderReadoutAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderReadoutAudit.java) 随所有场景的播放及视频录制逐 tick 检查表盘、颜色、比较器、红石线和显示板。独立物理夹具验证加速时低于 100%、稳定带载接近 100%、正向动力不足时过载减速、断供惰行、空载稳速为 0%、旧脚本读数被清除及重播清空缓存；粉碎轮夹具覆盖同向差速、反向差速、对转和同步，按解析式核对两端反作用、角动量及加工耗能。

- 补充教程入口：[DifferentialPonderPlugin](../src/main/java/com/diliupengyun/differential_create/client/ponder/DifferentialPonderPlugin.java)。只增加微分动力的独立条目，不移除或替换 Create 注册的故事板。
- 新增教程舞台：[DifferentialPonderScenes](../src/main/java/com/diliupengyun/differential_create/client/ponder/DifferentialPonderScenes.java)。普通教程使用独立的完整边界舞台，列车复用 Create 模板。共享舞台可用 `python tools/generate_ponder_structure.py` 确定性重建；底板使用白色混凝土与雪块，和原生 Create 思索底板一致。矮场景视图放大到 1.3 倍，`portable_docking` 使用 1.1 倍；较高的 `dynamics`、`steam_power` 和 `crusher_work` 使用 0.9 倍，保留顶部空间，并在宽屏、大界面比例下检查齿轮与高亮框不被裁切。自定义字幕通常固定在画面上方，蒸汽主题放在右下方空白处，并用同色描边标出目标方块，避免黑框盖住机器。
- 轴系运动：[PonderKinetics](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderKinetics.java)。每个预览世界持有独立状态；新教程和保留的原生教程共用生产扭转求解器、惯量注册表、几何速比、弹性接触、离合器限扭和强度判定。原生转速指令改成有限扭矩动力源的空载目标，不再直接设置机器速度。只指定从动齿轮的旧指令会按几何速比换算到动力源；缺少可见动力源的搭建示意使用额定扭矩为 1024 su/RPM 的外部驱动边界。已从动力源断开的支路不会凭空获得新动力，普通机械轴承也不会因其类继承关系成为动力源。转动角度取累计轴行程，暂停、慢放、跳转和重播沿用 Ponder 时间。轴承木梁单独从零速加入，用生产几何测量得到惯量和空气阻力，再随求解的输出角移动。

- 原版操作的局部适配：`BearingSceneMixin` 在原来的组装、拆解动作处补空手右击提示，将已移除的自动拆解设置说明改为手动操作；`SpeedControllerSceneMixin` 在原来调面板的时刻改变实际速比；`TrainControlsSceneMixin` 将已失效的滚轮限速提示改为档把提示。`SequencerSceneMixin` 把原脚本的角度动作交给生产位置控制器，并让轴承和结构跟随输出轴的实际行程，保留原来的动作角度、提示时刻和等待时间。链式传动箱按画面中红石线的强度同步真实倍率，平移后的展示副本也保留该状态。这些适配不重排舞台或改变镜头；其余机制差异优先通过原字幕键修正。
- 运行范围：[PonderSimulation](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderSimulation.java) 负责独立时钟和实际机器更新，不依赖渲染器是否缓存了方块实体。预览不启动完整服务端世界；通过 [PhysicsPreview](../src/main/java/com/diliupengyun/differential_create/kinetics/PhysicsPreview.java) 接入生产扭转、流体、加工、移动工具、列车纵向运动、矿车和接口对接逻辑。它的管网不进入服务端世界的更新列表，机器事件与列车作业上下文按线程隔离。展示用的入场、退场、镜头、结构拆分仍由 Ponder 编排。

  管网补充教程从关闭的入口阀门、干燥的下游透明管和空接收罐开始。先看停水，再转动手柄开阀，让实际水前沿、空气排出及接收罐液位变化与字幕同时发生；不预先灌满管道后才讲排气。智能管的岩浆过滤和水过滤分开讲解，分别观察停止输送与恢复输送。结果审计要求出现真实的水气前沿、排气、接收罐进水、拒收时液位稳定和改选水后恢复进水。
- 管道容器示例从取水切换到抽蜜时，先让平移的旧水源区域退场，并等待管内余水实际排出，再放置满蜜蜂巢和原位置的空接收罐，避免重叠水源覆盖蜂巢或余水混入接收罐。沿用原来的布局、镜头和字幕；结果检查要求蜂巢从蜜量 5 变为 0，接收罐只收到原生抽取产生的 250 mB 蜂蜜。另检查错误流体过滤和不足 250 mB 接收空间不会消耗蜂巢。

将编码器参数替换为本机已有的 FFmpeg 可执行文件。默认在独立测试客户端以 1200×900、GUI 缩放 2 录制实际注册的全部原生与新增教程，按场景去重，并单独录制移动式流体接口变体。每次正常调用 `PonderUI.tick()` 推进一个 tick，在 1/3、2/3 和末尾三个插值时刻捕获真实客户端画面，编码成 60 fps 的无声 MP4；不使用跳转取帧或 `whileSkipping`，机器、物料及粒子都随正常时间线更新。`-PponderVideoFps` 可指定 20～120 之间的 20 倍数；20 fps 只取 tick 末尾，会漏掉刻内反复伸缩等插值问题，不能用来证明动画平滑。录制持续到全部指令结束后再保留一秒，包括原版允许翻到下一页之后仍在进行的动作。操作系统可能限制实际窗口尺寸，以清单记录为准；编码器只在右侧或底部补至偶数像素，不缩放画面。

输出目录默认为 `build/ponder-video/recordings/`，每段视频附有编码日志；`coverage.json` 列出入口、场景与标称时长，`manifest.json` 记录帧数、实际视频时长、分辨率及自动审计问题。`ponderVideoScenes` 是录制过滤器，原版 ID 使用 `native-` 前缀；拼写错误会使任务失败。动画审计时间线使用包含视频名的文件名，避免物品／流体接口变体互相覆盖。录像模式执行动画审计，不执行常规客户端专项中的提示布局、索引重载等其他检查；两种模式应按验证目的分别使用。

**编码完成和自动断言通过不等于视觉复查通过。** 视觉复查要保留每个场景的检查记录：从视频按时间顺序检查全程画面，对装配、换向、加工接触等短暂事件加密到每 1～2 tick，对字幕和遮挡查看原尺寸，并在修复后重录受影响场景。记录实际采用的抽帧间隔，不把抽帧检查表述为观看了视频的每一帧。视频、检查索引、抽帧和临时分析脚本保留在忽略的 `build/` 中；录制器属于 `gameTest` 源集，不进入正式发布包。

蒸汽动力补充教程较高，字幕单独放在舞台右下方空白处。场景使用 0.9 倍缩放，避免在 960×720、GUI 缩放 3 时裁掉锅炉顶部；原版场景不受这些取景调整影响。

客户端专项在 `build/ponder/runs/` 下运行并自动退出，不打开玩家存档。它检查双语键、占位符、摘要入口、真实 Mixin 提示、折叠／展开布局、护目镜数值显示、两次索引重载，以及全部微分动力故事板的完整播放；同时将实际注册表与 Create 单独注册的结果比较，检查全部原版条目的模板、故事板、标签、顺序均保留，并在两次索引重载后重复检查；再编译各入口的完整故事板列表，检查重复主题。播放检查遍历演示期间的实际方块实体与运动，不依赖教程的固定坐标或结束姿态；逐项收集失败后统一报告。比较器输入端、管口、滑架轴线、铁轨连接、压力机工作空间、耕地和多方块储罐会单独核对；弹射器必须实际发射，齿轮箱必须实际驱动、反转、在输入仍转动时保持到位，并等待新脉冲再次启动。

动力场景另测有限加速、带载惰行、分离后的独立反转、被动部件不生成功率和场景 NBT 更新后保持物理状态。全部自定义主题及流体接口变体还从头重播整段动画，逐 tick 比较转速、输入／输出轴角度、附加输出角度与结构位置，检查中途跳转和状态遗留。预览速度与接触弹性状态由本地求解器保管，避免原版教程修改局部 NBT 时清掉服务端专用字段而破坏演示。可编程齿轮箱预览复用生产环境的双轴位置控制器、有限传递扭矩和制动器。

默认还播放传动、加工、流体、结构和列车等代表性原生教程，其中包含冲压机、机械手、置物台和粉碎轮，并将 19 个主题、原版齿轮场景和物品提示的真实客户端截图保存到 `build/ponder/previews/`。启用 `-PponderAudit=true` 时，遍历所有已注册的 Create 原版教程（当前 167 个独立场景），不再仅检查已翻译主题；对各主题关键帧和结束状态截图，单独保留流体接口版本。截图及对应的方块、转速、角度和结构位置保存在 `build/ponder/previews/audit/`，`manifest.txt` 列出本次实际捕获的帧名与时刻。追加 `-PponderCapture=false` 可只运行完整回放、保存时间线；`-PponderCaptureScenes=<逗号分隔的主题 ID>` 只限制截图范围，不缩小回放检查范围。

追加 `-PponderFrameAudit=<主题 ID>` 可放大并每两 tick 捕获一次该主题的时间轴，保存到 `audit/frames/<主题 ID>/`。用逗号分隔多个 ID 时保留正常取景，保存到 `audit/frames/selected/`；原版主题 ID 使用 `native-` 前缀。使用 `all` 时录制全部审计场景，自定义场景每两 tick、原版场景每四 tick 一帧，保存到 `audit/frames/all/`。截图等待界面淡入时保持指定的场景时刻，并校验实际时刻，避免把过渡结束后的画面误记为过渡帧。快速回放沿用思索自身的跳转刷新流程，确保新出现或更换的机器也会正常更新。最终通过标记为 `DC_PONDER_CLIENT_PASS`。播放、运动审计和重播一致性检查一直运行到所有指令结束；原生 `markAsFinished()` 开放下一页后的动作也参加检查。截图仍按原生 UI 时间轴取样，不将时间轴之外的额外动作算作截图覆盖。

[PonderTransmissionAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderTransmissionAudit.java) 另核对链式传动箱的输入不被输出指令改速、输入侧倍速、输出侧减速和模拟信号调节；核对速比控制器的驱动目标不被输出倍率重写，并覆盖“下一页”开放后的反转；核对可编程齿轮箱在输入持续运行时实际正转、反转和保持到位。倍率比较取一秒内的实际显示行程，允许生产模型中的高频扭转振动和加速负载造成的短暂降速。原版齿轮接表另分别检查正常播放与跳转播放，未接通的转速表及负载表不得自行提供动力。

[PonderAnimationAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderAnimationAudit.java) 对自定义和保留的原版场景逐 tick 检查输入轴、独立输出轴与附加结构输出角度在插值边界处连续；部件并入装配时允许一次可见相位校正，并按实际显示位置和同一求解器组件核对已稳定的刚性连接（包括齿轮中心轴与分轴端面）；红石反转齿轮箱另核对通电时只反转输出侧、输入侧保持原方向。分轴顶点由 [PonderShaftAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderShaftAudit.java) 另行检查；另检查自定义滑架没有驶出龙门轴、列车轮角与车身行程一致、列车速度连续、矿车没有与载荷分离。审计模式在 `audit/timelines/` 保存每个入口的完整时间线，包括每 tick 的角度、结构位置与转角、淡入淡出进度、方块变化及车辆位移，供连续帧排查使用。

[PonderMaterialAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderMaterialAudit.java) 检查物料来源和实际加工接触。原版冲压机与机械手教程的连续转速略低于脚本标称值，原来相隔 15 tick 的第二次传送带投料可能被拒绝；[PonderBeltInput](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderBeltInput.java) 等待入口腾出空间后再投放，并只跟踪实际接收的物料。产物由已有原料原位转化，不凭固定时刻删除、生成。冲压机调用生产配方，在压头触底后出板、回程后放行；机械手保留原有手臂动作，在工作点研磨已到达的石英。布局、镜头、字幕和原料安排沿用原版；冲压机结尾仅补足最后一次回程所需的等待。测试分别核对一份置物台原料、两份传送带原料与三份产物，检查出料时压头或机械手已经接触物料，并覆盖正常播放与跳转重播。粉碎轮另验证矿石从空中落入间隙并被真实加工库存接收。

[PonderFanAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderFanAudit.java) 直接调用已应用 Mixin 的鼓风机渲染器并采集模型顶点，核对叶片与轴的相位，覆盖六个朝向、帧内插值、加减速、反转、惰行、暂停和重置。原生气流方向与鼓风加工教程也参加播放检查。自定义加工场景另核对原料持续可见、变速期间原生计时仍每 tick 减一，且只有计时完成才出现产物。其他部件的独立动画（例如搅拌头、传送带表面滚动）不能仅凭轴系检查通过就视为已经验证。

[PonderShaftAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderShaftAudit.java) 在每个场景逐 tick 调用实际的普通分轴／十字齿轮箱渲染器，采集各端面 `SHAFT_HALF` 的顶点，以实际相邻完整轴的 `shaftAngleOf` 为独立参照。只需一个端面接轴就会检查，未展示的模板副本不算接触，避免只调用待测相位方法而漏掉实际渲染分支。[ShaftRenderingAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/ShaftRenderingAudit.java) 另对五类部件、三个轴向、所有输入面和两种模型偏移构建测试场景，同时验证普通网格及真实 Flywheel Visual 的构造、更新和重建；覆盖帧内插值、反转、惰行、暂停，以及拆掉离合器输出轴后的相位延续。Flywheel 检查使用内存实例接收器读取最终着色器参数，不依赖显卡后端绘制结果。

蒸汽场景另外比较原生连杆渲染器读取的曲柄角与动力轴渲染角。“安装蒸汽引擎”还按画面位置检查同轴端部和相邻齿轮的转速、相位：允许弹性轴加速时的小幅速度振荡，但自完整显露起，轴端或齿轮相位偏差不得超过 0.2°，接合 30 tick 后的速度差不得超过 2 RPM。播放中不允许已显露的动力轴或齿轮消失；结束时的八根动力轴、五个输出齿轮必须完整，并验证其确实消耗蒸汽后产生运动。该原生场景不要求在有限预热时间内达到 450 RPM；独立世界夹具另验证供水、供汽与 512 RPM 调速。此检查用于发现各自转动连续、彼此却接错或错相的情况，不能只以单个部件的连续性作为装配正确的依据。

[PonderSceneStateAudit](../src/gameTest/java/com/diliupengyun/differential_create/tests/PonderSceneStateAudit.java) 对全部自定义入口逐 tick 核对模型与机器状态：外部动力入口须为底板侧缘 y=0 的大齿轮，实际啮合上方小齿轮并与舞台内元件连通；独立动力入口的接入齿轮不得互相啮合；锅炉不得保留普通储罐窗口，储罐成员、控制器、顶底接缝须一致；泵须能沿实际可见的轴、齿轮追溯到明确登记的动力输入端或马达，不能只因泵在旋转就判定供能正确；蒸汽教程须进入调速区并实际断汽惰行；行驶列车须有锅炉、水和软管，全部锅炉成员、供热方块与含燃料的容器须跟随同一车身位移，两组车轮下方须保持铁轨，软管端点须随模型同步移动且管线不得穿过车体碰撞形状。还检查粉碎轮的同向差速实例、弹射器的实际改向，以及可见部件在退场完成前不得被换成另一种方块。时间线额外记录锅炉窗口、供汽、表盘、液量、软管端点与弹射目标。

收割演示使用生产收割行程和额定阻力，在刀头接触成熟作物后施加切割负载，走完切割行程再收割；空走和回程取消该负载。粉碎轮第二阶段使用同向差速演示；投料阶段在间隙中建立有效、朝下的原生控制器，让掉落矿石实际进入其加工库存，不再用定时删除模拟入料，也不在入料路径上叠加物品图标；弹射器最后一阶段确实改变落点并重新蓄能。锅炉、管道与机器替换继续保留原生滑动过渡。

龙门轴的脚本放置不会自动执行普通世界的邻接更新。收割与两种移动接口场景在显示前调用 Create 的邻接规则，为同向相连的轴设置首段、中段和尾段模型；中间不得残留独立轴段的双端帽。场景状态检查按实际邻居与朝向逐 tick 核对 `PART` 属性，避免动力连通但外观仍断开的情况。

全部微分动力故事板还逐 tick 检查可见显示区域的方块归属，过渡期间也不允许同一坐标归属两个区域。这既会造成重叠绘制，也会使同一机器实体被多个区域重复更新。部件替换沿用 Create 原生教程的滑动过渡：旧部件先用 `hideSection` 退场，等待 15 tick 后在隐藏状态下替换，再用 `showSection` 入场，等待 15 tick 后继续演示。退场区域仍读取场景里的实际方块，因此必须等它完全隐藏后再更换模型。新区域入场前先移除该坐标的旧显示归属，整体显示的结构内部也不再重复显示单个方块；列车教程保留模板的铁轨与车站，在车体首次显露前清除旧车体、储罐和汽笛，再构建新底盘。

这项检查不代替[动力](KINETIC_COVERAGE.md)、[流体](FLUID_COVERAGE.md)、[动态结构](CONTRAPTIONS.md)、[移动式接口](PORTABLE_STORAGE.md)与[列车](TRAINS.md)的实际世界行为测试。

列车演示的燃料检查通过 Create 的 `MountedStorageManager.getFuelItems()` 读取可用库存，不能仅因某个容器中装着煤就视为能够供燃料；保险库黑名单和内部库存排除必须同样生效。行驶时另外核对独立普通水罐中存在水，避免把不参加挂载流体库存的锅炉自身误算为备用水箱。
