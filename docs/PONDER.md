# 微分动力：思索与物品提示

微分动力（Differential Create）的教程按当前物理实现编写，中英文同步维护。仍适用的 Create 搭建、配方、过滤和物流步骤继续保留；旧应力容量、固定轴速、泵送范围、接口瞬停与列车滚轮限速等说明已经替换。

## 文案与阅读时长

正文每屏只讲当前演示的操作或机制。详细数值、拆装操作和边界条件仍可在物品提示及机制文档中查询，不把完整说明书塞进一个短字幕。标题始终显示，不按短字幕计时。

[PonderTextAudit](../src/main/java/com/diliupengyun/differential_create/tests/PonderTextAudit.java) 随思索客户端测试运行，从真实编排中读取每条字幕的显示时长，并检查中英文。检查范围包括全部自定义主题，以及本模组改写的原生场景中的全部正文，包括继续沿用 Create 翻译的段落。

- 以每秒 **5 个汉字、3 个单词**作为通过标准，同时记录每秒 8 字、5 词的快速阅读用时。
- 混排文字的时间相加：`汉字数 / 5 + 英文、按键及数值词数 / 3`。标点和格式符不计；连字符、斜杠分隔的词分别计数。
- 按正常播放的每秒 20 tick 计算，扣除淡入淡出；不依赖暂停、慢速阅读或额外拖长停留时间。
- 自定义正文保留原来的 90 tick 阅读时间和 100 tick 编排间隔。原生场景保留各自时长，超量时精简文字。
- `markAsFinished()` 只开放下一场景，现有字幕仍继续计时；检查不会误把时间轴结束标记当成字幕消失。

统计明细输出至 `build/ponder/previews/text-readability.json`；超出慢速阅读预算会使客户端检查失败。此次核对涉及 43 个场景、199 段正文，共 398 条语言读数；原先 159 段至少有一种语言超出慢速预算，其中 121 条语言读数连快速预算也超出。精简后两种语言均满足慢速预算。

### 与机制对应的修正

| 文案问题 | 当前说明及实现依据 |
| --- | --- |
| 任意车载容器都可供燃料 | 列车和熔炉矿车均从 Create 的 `getFuelItems()` 取燃料，保险库被燃料黑名单排除；熔炉矿车只补煤、木炭。列车水源还需独立普通储罐。见 [列车说明](TRAINS.md)、`TrainPhysics.feedFuel`、`MountedBoilerInventoryMixin`，以及 Create 的 `OrientedContraptionEntity`。 |
| 换档快捷键似乎无需档把 | 车上必须装有档把，键盘换档与自动换档才生效。见 `TrainControlsClient.shift`、`TrainPhysics.hasLever/shift`。 |
| 司机会自行启动自动驾驶，英文称任意生物均可 | 明确司机需要时刻表；原生教程限定控制器前的合格座位乘客或烈焰人燃烧室。驾驶与换档条件见 `TrainPhysics`、Create 的 `CarriageContraptionEntity.checkConductors`。 |
| 速比面板每格均为 1/16 | 面板刻度非线性；Ctrl＋右键输入数值按 1/16 量化。见 `RatioScale`、`RatioValueBehaviour`、`RatioPrecisionScreen`。 |
| 所有机器只在加工时耗能 | 限定为加工负载；风扇和移动结构仍有风阻。见 `MachineActivity.impact/loadTorque/quadraticDrag`。 |
| 过载必然击断全网最弱部件 | 改为部件承受扭矩超过自身强度时断裂；判断依据是局部受力。见 `TorsionSolver` 的强度越界判断。 |
| 管网与泵的方向说明容易等同即时水流方向 | 区分增压方向与惯性造成的流量变化；阀门阻断空气和液体，智能管允许空气通过。见 `FluidKinetics`、`QueuedFluidSolver`。 |

其余主题对照了 `ClutchControl`、`LoadFactor/LoadGaugeScale`、`SpeedGaugeRangeBehaviour`、`ContraptionPhysics/ContraptionActorWork`、`MachineWork`、`BacktankCharge`、`EjectorCharge`、`CrushingWork`、`SourcePhysics/SteamGovernor`、`DockingState`、`MinecartPhysics`、`SequencerMotion` 与 `FanProcessingRate`。精简时保留实际操作所需的前提，避免把有限制动、需能量完成工作或无可用读数改写成无条件保证。

## 物品栏提示

Create 的 Shift 摘要和 Ctrl 操作提示机制继续沿用。按住 Shift 后，按键提示仍保留，Shift 字样变白。未展开时只保留原生按键提示与末尾动力统计，不放常驻解释段落。末尾的“应力消耗”改为“扭矩消耗”，继续使用灰色标题、三格彩色等级条与低／中／高分级；戴工程师护目镜时，等级文字替换为精确的 `su/RPM` 数值。Shift 不控制这一统计行是否显示精确数值。动力源显示起动／输出扭矩。泵、粉碎轮与动态结构显示“随工况变化”，不会伪造一个固定消耗或等级。

本体转动惯量和结构强度放在 Shift 展开的“机械属性”小节，用缩进灰字和较亮的数值排列在扭矩统计之前。扭矩统计始终留在末尾；本体参数不再占用折叠提示的空间。

原版离合器既不消耗应力，也不提供应力容量，没有对应的常驻统计条。微分动力新增的离合器限扭放入 Shift 的“机械属性”，直接显示普通／黄铜离合器完全接合时的额定上限；不套用动力源容量的“小／中／大”分级。

物品栏只能描述裸部件。组装后的结构质量、真实管网水头、供汽、工作状态与瞬时功率需要在世界中查看护目镜或仪表。额定作业阻力不表示机器待机时也消耗该扭矩。负载表整体零速时仍沿用当前起动预算，教程没有宣称尚未接入的时间右极限求值。

新增物品也已接入摘要，包括黄铜离合器、复合摩擦片、供汽软管、冷凝管和列车档把。原版护目镜、背罐和飞轮的旧文字一并更新。

## 维护与验证

思索是实时绘制的教学场景：NBT 模板提供方块和初始状态，Java 故事板按 tick 安排显露、移动、提示与操作；`PonderLevel` 是独立的客户端预览世界。微分动力把轴系运动接入共享扭转求解器，但这不等于整个预览都运行完整服务端物理。判断一致性必须同时检查场景脚本、实际机器状态和最终渲染，不能只看求解器的角度连续。

- 注册与替换入口：[DifferentialPonderPlugin](../src/main/java/com/diliupengyun/differential_create/client/ponder/DifferentialPonderPlugin.java)。只替换 Create 所属的目标故事板，保留其标签与排序约束；重新加载索引时重新执行。
- 舞台：[DifferentialPonderScenes](../src/main/java/com/diliupengyun/differential_create/client/ponder/DifferentialPonderScenes.java)。普通教程使用独立的完整边界舞台，列车复用 Create 模板。共享舞台可用 `python tools/generate_ponder_structure.py` 确定性重建。
- 轴系运动：[PonderKinetics](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderKinetics.java)。每个预览世界持有独立状态；新教程和保留的原生教程共用生产扭转求解器、惯量注册表、几何速比、弹性接触、离合器限扭和强度判定。原生转速指令改成有限扭矩动力源的空载目标，不再直接设置机器速度。只指定从动齿轮的旧指令会按几何速比换算到动力源；缺少可见动力源的搭建示意使用额定扭矩为 1024 su/RPM 的外部驱动边界。已从动力源断开的支路不会凭空获得新动力，普通机械轴承也不会因其类继承关系成为动力源。转动角度取累计轴行程，暂停、慢放、跳转和重播沿用 Ponder 时间。轴承木梁单独从零速加入，用生产几何测量得到惯量和空气阻力，再随求解的输出角移动。
- 动画连续性：轴系重新连接或切换速比时，求解器需要重新校准接触相位；画面另存连续的显示角度，避免校准使轴和齿轮突然跳转。收割机按移动刀头的实际接触位置收割，接口滑架的往返行程保持在龙门轴上。列车和矿车的演示轨迹使用有限加减速；列车挂空挡后继续滑行，反转前先减速，车轮逐 tick 使用车身实际位移计算角度，矿车与载荷使用同一位移。
- 鼓风机：普通渲染器的叶片原先绕过共享角度，仍按“总时间 × 当前转速”并附加倍速、最低转速和上限计算；输入变化会造成跳角。`EncasedFanRendererMixin` 与 `FanVisualMixin` 将叶片固定为和输入轴同速、同相位，停转时保留角度。预览积分更新转速后通知风机重建气流，使方向和范围跟随当前轴速。`fan_work` 的风机和岩浆位于置物台上方的风路，原料在真实 `AirCurrent` 扫描、`FanWork` 和配方处理完成后变成产物，删除了同一 tick 直接替换成品的脚本。服务端加工分支只对场景明确启用的风机开放，随预览重播重置。
- 原生场景的装配位置：[PonderDisplayTopology](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderDisplayTopology.java) 按显示区域的变换连接平移后的轴和齿轮，模板里尚未使用的其他示例不参加计算。“安装蒸汽引擎”把不同坐标的锅炉、汽缸和齿轮移到一起，并逐个揭示同一套已装配机器；这一场景为当前锅炉提前声明完整轴系，在揭示前建立相位，切换锅炉时退出旧轴系。新显露的预装配部件使用所属轴系的初始速度，之后仍由有限扭矩积分，避免把展示步骤当成高速接入静止轴。蒸汽动力轴读取蒸汽引擎的容量，并调用生产环境的汽缸／512 RPM 调速曲线；原生 16／64 转速指令在这一场景中分别表示被动供热／燃烧器供汽。
- 范围：预览不启动完整服务端世界。管内液流、列车和矿车行驶仍是教程脚本；移动式接口的制动与开放顺序由脚本指定，滑架位置取预览轴系积分的行程；蒸汽供给以声明的锅炉边界输入生产汽缸／调速器曲线。预览轴系的动力学检查不代替完整流体、运输和机器配方测试。
- 锅炉与列车场景：组装锅炉时同步多方块外壳、关闭玻璃窗并更新表盘；声明的供水写入同一份锅炉供汽状态，双缸轴系直接读取生产汽缸曲线，原生喷汽与断汽状态也随之更新。动力泵由可见马达和啮合齿轮驱动。列车动力与驾驶场景共用双轮组平板底盘，后部安装 3×3×2 的低矮锅炉和两座可见热源，前部露出动力轮组、软管接口与冷凝升级；车板上的木桶储存燃料，独立普通水罐储水。保险库沿用原生燃料黑名单，不作为供燃料容器，锅炉本体也不作为备用水箱。锅炉、水、燃料、热源和软管一起随车移动，两组车轮均按车身位移旋转，往返行程保持在轨道范围内。[PonderHoseElement](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderHoseElement.java) 复用游戏中的软管网格，并让两端跟随各自显示区域移动。连接端口与操纵台分开，操作图标先完成展示再出现对应文字；长说明固定在画面上方，避免遮住车体或让指示线滞留在行驶前的位置。
- 英文默认文本及顺序：[PonderLesson](../src/main/java/com/diliupengyun/differential_create/client/ponder/PonderLesson.java)。翻译分别位于 [en_us.json](../src/main/resources/assets/differentialcreate/lang/en_us.json) 与 [zh_cn.json](../src/main/resources/assets/differentialcreate/lang/zh_cn.json)。更改段落顺序时同步更新 `text_N`。
- 物品栏读数：[KineticItemTooltip](../src/main/java/com/diliupengyun/differential_create/client/KineticItemTooltip.java)。本体惯量与强度直接读取生产注册表，避免另存一份易过期的参数。

客户端专项在 `build/ponder/runs/` 下运行并自动退出，不打开玩家存档。它检查双语键、占位符、摘要入口、真实 Mixin 提示、折叠／展开布局、护目镜数值显示、两次索引重载，以及全部微分动力故事板的完整播放；同时编译各入口的原生故事板列表，检查重复主题。播放检查遍历演示期间的实际方块实体与运动，不依赖教程的固定坐标或结束姿态；逐项收集失败后统一报告。比较器输入端、管口、滑架轴线、铁轨连接、压力机工作空间、耕地和多方块储罐会单独核对；弹射器必须实际发射，齿轮箱必须实际驱动、反转、在输入仍转动时保持到位，并等待新脉冲再次启动。

动力场景另测有限加速、带载惰行、分离后的独立反转、被动部件不生成功率和场景 NBT 更新后保持物理状态。全部自定义主题及流体接口变体还从头重播整段动画，逐 tick 比较转速、输入／输出轴角度、附加输出角度与结构位置，检查中途跳转和状态遗留。预览速度与接触弹性状态由本地求解器保管，避免原版教程修改局部 NBT 时清掉服务端专用字段而破坏演示。可编程齿轮箱预览复用生产环境的双轴位置控制器、有限传递扭矩和制动器。

默认还播放 13 个保留的原生动力教程，并将 20 个主题和物品提示的真实客户端截图保存到 `build/ponder/previews/`。启用 `-PponderAudit=true` 时，扩大到 32 个保留的原版教程，对每个主题的全部关键帧和结束状态截图，单独保留流体接口版本；截图及对应的方块、转速、角度和结构位置保存在 `build/ponder/previews/audit/`，`manifest.txt` 列出本次实际捕获的帧名与时刻。

追加 `-PponderFrameAudit=<主题 ID>` 可放大并每两 tick 捕获一次该主题的时间轴，保存到 `audit/frames/<主题 ID>/`。用逗号分隔多个 ID 时保留正常取景，保存到 `audit/frames/selected/`；原版主题 ID 使用 `native-` 前缀。使用 `all` 时录制 53 个场景变体，自定义场景每两 tick、原版场景每四 tick 一帧，保存到 `audit/frames/all/`。截图等待界面淡入时保持指定的场景时刻，并校验实际时刻，避免把过渡结束后的画面误记为过渡帧。快速回放沿用思索自身的跳转刷新流程，确保新出现或更换的机器也会正常更新。最终通过标记为 `DC_PONDER_CLIENT_PASS`。原生场景有时在 `markAsFinished()` 开放下一页后继续安排动作，这些额外动作不能算作已被时间轴录制覆盖。

[PonderAnimationAudit](../src/main/java/com/diliupengyun/differential_create/tests/PonderAnimationAudit.java) 对自定义和保留的原版场景逐 tick 检查输入轴、独立输出轴与附加结构输出角度在插值边界处连续；另检查自定义滑架没有驶出龙门轴、列车轮角与车身行程一致、列车速度连续、矿车没有与载荷分离。审计模式在 `audit/timelines/` 保存每个入口的完整时间线，包括每 tick 的角度、结构位置与转角、淡入淡出进度、方块变化及车辆位移，供连续帧排查使用。

[PonderFanAudit](../src/main/java/com/diliupengyun/differential_create/tests/PonderFanAudit.java) 直接调用已应用 Mixin 的鼓风机渲染器并采集模型顶点，核对叶片与轴的相位，覆盖六个朝向、帧内插值、加减速、反转、惰行、暂停和重置。原生气流方向与鼓风加工教程也参加播放检查。自定义加工场景另核对原料持续可见、剩余工作量逐 tick 按实际 RPM 减少，且只有完成工作才出现产物。其他部件的独立动画（例如搅拌头、传送带表面滚动）不能仅凭轴系检查通过就视为已经验证。

蒸汽场景另外比较原生连杆渲染器读取的曲柄角与动力轴渲染角。“安装蒸汽引擎”还按画面位置检查同轴端部和相邻齿轮的转速、相位：允许弹性轴加速时的小幅速度振荡，但自完整显露起，轴端或齿轮相位偏差不得超过 0.2°，接合 30 tick 后的速度差不得超过 2 RPM。播放中不允许已显露的动力轴或齿轮消失；结束时的八根动力轴、五个输出齿轮必须完整，空载动力轴须进入 450 RPM 以上的调速区间。此检查用于发现各自转动连续、彼此却接错或错相的情况，不能只以单个部件的连续性作为装配正确的依据。

[PonderSceneStateAudit](../src/main/java/com/diliupengyun/differential_create/tests/PonderSceneStateAudit.java) 对全部自定义入口逐 tick 核对模型与机器状态：锅炉不得保留普通储罐窗口，储罐成员、控制器、顶底接缝须一致；泵须能沿实际传动连接追溯到可见马达；蒸汽教程须进入调速区并实际断汽惰行；行驶列车须有锅炉、水和软管，全部锅炉成员、供热方块与含燃料的容器须跟随同一车身位移，两组车轮下方须保持铁轨，软管端点须随模型同步移动且管线不得穿过车体碰撞形状。还检查粉碎轮的同向差速实例、弹射器的实际改向，以及可见部件在退场完成前不得被换成另一种方块。时间线额外记录锅炉窗口、供汽、表盘、液量、软管端点与弹射目标。

收割演示使用生产收割行程和额定阻力，在刀头接触成熟作物后施加切割负载，走完切割行程再收割；空走和回程取消该负载。粉碎轮第二阶段使用同向差速演示，弹射器最后一阶段确实改变落点并重新蓄能。锅炉、管道与机器替换继续保留原生滑动过渡。

龙门轴的脚本放置不会自动执行普通世界的邻接更新。收割与两种移动接口场景在显示前调用 Create 的邻接规则，为同向相连的轴设置首段、中段和尾段模型；中间不得残留独立轴段的双端帽。场景状态检查按实际邻居与朝向逐 tick 核对 `PART` 属性，避免动力连通但外观仍断开的情况。

全部微分动力故事板还逐 tick 检查可见显示区域的方块归属，过渡期间也不允许同一坐标归属两个区域。这既会造成重叠绘制，也会使同一机器实体被多个区域重复更新。部件替换沿用 Create 原生教程的滑动过渡：旧部件先用 `hideSection` 退场，等待 15 tick 后在隐藏状态下替换，再用 `showSection` 入场，等待 15 tick 后继续演示。退场区域仍读取场景里的实际方块，因此必须等它完全隐藏后再更换模型。新区域入场前先移除该坐标的旧显示归属，整体显示的结构内部也不再重复显示单个方块；列车教程保留模板的铁轨与车站，在车体首次显露前清除旧车体、储罐和汽笛，再构建新底盘。

这项检查不代替[动力](KINETIC_COVERAGE.md)、[流体](FLUID_COVERAGE.md)、[动态结构](CONTRAPTIONS.md)、[移动式接口](PORTABLE_STORAGE.md)与[列车](TRAINS.md)的实际世界行为测试。

列车演示的燃料检查通过 Create 的 `MountedStorageManager.getFuelItems()` 读取可用库存，不能仅因某个容器中装着煤就视为能够供燃料；保险库黑名单和内部库存排除必须同样生效。行驶时另外核对独立普通水罐中存在水，避免把不参加挂载流体库存的锅炉自身误算为备用水箱。
