# 蒸汽机与供水体验指南

微分动力的蒸汽机用有限扭矩和有限供汽功率驱动轴，负载与惯量决定实际转速。调速器逐渐关小进汽并降低耗水；断汽后保留转动储能。

适用于 Minecraft 1.21.1、NeoForge 21.1.238、Create 6.0.10-281、Java 21。安装与构建见 [README](../README.md#构建与验证)，动力方程见 [设计文档](../DESIGN.md#2-动力源)。多人游戏两端应使用相同构建。

## 从静止启动

1. 在创造测试世界搭建持续供水、持续加热的锅炉，先安装一台蒸汽引擎。护目镜显示的有效锅炉等级应至少为 1。
2. 用独立的创造马达驱动供水泵，保持水源、热量与燃料供应，先把供水和蒸汽输出分开观察。
3. 引擎正确连接动力轴，输出只延伸普通传动杆。飞轮、转速表与机器会增加惯量或负载，稍后再接入。
4. 戴护目镜直接观察动力轴；比较转速绝对值，负号仅表示旋转方向。从开始有效供汽、轴接近静止时计时。
5. 检查转速上升、接近目标时的“调速收汽”状态，以及按实际进汽出现的汽缸排汽。

默认满供汽、单轴无外接负载、正常 20 TPS 时：

| 游戏内时间 | 预期绝对转速 | 运行状态 |
| --- | ---: | --- |
| 0.75 秒 | 约 128 RPM | 缸压限制扭矩 |
| 1.5 秒 | 约 256 RPM | 开始进入恒功率区 |
| 3.05 秒 | 约 448 RPM | 开始逐渐收汽 |
| 4.2 秒 | 约 500 RPM | 进汽与耗水减少，升速放缓 |
| 6 秒 | 约 511 RPM | 接近调速目标 |
| 1 分钟 | 约 512 RPM | 进汽与耗水接近零 |

已有转动储能不会因改变供汽而自动清零。直接接入惯量为 0.5 的飞轮后，总惯量由 0.1 增为 0.6，低速空载爬升时间约为六倍。

有作弊权限时可用 `/tick sprint 1200t` 快进一分钟游戏时间，用 `/tick sprint stop` 提前结束。快进也会同步推进燃料、水泵和其他机器。

## 带载、断汽与供水

- **带载与卸载**：在同样的一台引擎输出端接鼓风机，再供汽。风扇阻力随转速增长，会形成负载与驱动平衡的转速；移除风扇后向 512 RPM 加速，重新带载降速时增加进汽。闲置冲压机等等待加工的机器没有工作负载。
- **减少供汽**：减少供水或热量后，有效锅炉等级下降，每台可用功率和恒功率区起点降低。转速继续积分变化；完全空载时可能只是加速变慢，有负载时可能降速。
- **断汽惰行**：断开供水并耗尽不足 1 mB 的已付余量，确认动力轴显示“无供汽”。也可移走全部热源。仅停止投燃料未必断汽，剩余热源仍可能提供被动供热。无负载的轴保持匀速，有机器负载则消耗动能减速。
- **飞轮供水**：切断驱动后，泵的转动储能和管内水流惯性可以继续供水，水流也可以反拖泵。实际输送仍受源库存、排气路径、连接和接收能力限制。观察输入罐实际水量，锅炉显示当前实际付水，不能依靠旧采样维持动力。
- **并联与反转**：从属引擎按上游方向指令和速比选向；没有上游动力时跟随实际惰行方向，完全静止时保留设置。主动反转先制动原方向，再经过零速反向加速，改变方向设置不会瞬间重设轴速。
- **外部超速**：外部动力或当前读档状态使轴超过 512 RPM 时，进汽与耗水关闭，轴保留实际速度。切断供汽后汽缸排汽停止，同向超速不会自动受到蒸汽机制动。

将供水泵接回蒸汽输出时，泵本身的持续负载也参与转速平衡。供水下降可能进一步降低供汽；先确认独立供水场景，再尝试自供水和飞轮储能。

## 与车载引擎一致的耗水

每个锅炉汇总有效输出引擎的本刻进汽需求，水泵只支付尚未付清的水量。模拟填充不扣水，多个接口不会重复支付；超过需求的水留在原有管网。锅炉仍没有可存取的液体库存，仅保存不足 1 mB 的整数扣水余量。供水读数与存档保存的是当前需求、实际付水与供水比例，不使用原版近期最大流量样本。

同向运转时，单机需求为 `200 × 进汽开度 × min(每台供汽份额, max(16, |输入 RPM|) / 256) × 调速器开度` mB/s（20 TPS）。静态引擎的手动进汽开度为 1，车载采用驾驶开度；同样条件下的曲线与耗水相同。0～16 RPM 保留少量充汽与漏汽消耗，关阀时为零；换向不退还吸收的轴能量。没有储汽或真实汽缸阀门时序模型。

单机足额供汽、全开时：起步 12.5 mB/s，128 RPM 为 100 mB/s，256～448 RPM 为 200 mB/s，480 RPM 为 100 mB/s，512 RPM 或同向超速为零。静态泵的流量不足也可以提供部分转矩，不再要求起步前持续输入 10 mB/t。单机额定功率上限和 512 RPM 调速目标保持一致。

## 当前参数与读数

| 参数 | 默认值或规则 |
| --- | --- |
| 单机缸压扭矩上限 | 1024 su/RPM；随 Create 容量配置成比例变化 |
| 单机额定功率 | 262,144 su；每台最多利用一级供汽 |
| 满供汽恒功率区起点 | 256 RPM；供汽不足时按每台供汽比例降低 |
| 收汽区间与目标 | 448–512 RPM，目标为 512 RPM |
| 动力轴惯量 | 0.1 su/RPM³ |
| 满级锅炉、18 台引擎 | 总可用功率为 4,718,592 su |

锅炉生产上限受尺寸与热量共同限制，被动供热为 1/8 等效等级。18 级锅炉只装一台时，仍只能利用该单机的 262,144 su；未连接有效输出的引擎不消耗水，其供汽份额不会重新分配。实际水量不足时，已付水量 / 当前需求同时缩小转矩与可用功率。

普通护目镜视图显示惯量、转速、驱动状态、调速目标、收汽比例、负载率和扭矩。按住潜行键切到能量视图，查看本体与所属网络的动能、弹性势能、输出或吸收功率，以及收汽减少的潜在功率；后者没有被输入，也没有被旁通消耗。

负载率是网络持续负载需求与当前可用驱动力之比，空载加速仍为 0%；飞轮储能不计作持续负载。锅炉显示当前可用理论功率预算。排汽跟随实际进汽；调速器全关或无水时停止。

## 模型限制与验证范围

当前模型没有蒸汽机内部阻尼，不模拟真实压力储量、温度、汽缸阀门时序或建立压力的等待过程。调速器减少实际进汽、驱动与耗水；机器工作负载、风扇阻力及离合器打滑仍会耗能，弹性传动允许持续振荡。

供汽只读取当前已加载、位置与朝向有效的发动机—储罐—锅炉控制器链。任一环不可用时停止驱动并保留惰行，关联恢复后继续供能；查询不会主动加载区块，也不使用存档旧效率作为供汽回退。

水泵采用[虚拟空气与有序流体模型](FLUIDS.md)，支持空管引液、液体重力与反拖，困气时会阻断灌注。锅炉沿用原生流体接口，按共享动力曲线限制实际接水量；管网不模拟气体压缩、真空或同口逆向交换。

正式回归见 [SteamEngineTests](../src/main/java/com/diliupengyun/differential_create/tests/SteamEngineTests.java) 和 [PumpPhysicsTests](../src/main/java/com/diliupengyun/differential_create/tests/PumpPhysicsTests.java)，构建与运行命令见 [README](../README.md#构建与验证)。蒸汽测试由夹具控制热量与供水，泵测试另行验证真实输水及管道 NBT 恢复；完整燃烧器燃料链、复杂管网、自然跨区块长期卸载重载和多人同步仍需专项实测。
